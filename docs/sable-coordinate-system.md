# Sable 坐标与方向规范

本文是 Sable 子世界方块渲染的坐标、旋转和验证标准。以后新增方块、迁移 TreePhysics 行为、修复方向问题，都必须先按本文确定映射，再实现和验证。本文约定的是 Sable 的最终结果；TreePhysics 是已通过游戏内验证的视觉与行为基准，但 TreePhysics 中间旋转数值不能未经校准直接复制。

相关文档：

- [Sable 方块注册](sable/Bedrock-Sable.zh-CN.md)：注册表、模型类型、状态和构建产物。
- [分池原木朝向错误复盘](../sable/docs/sublevel-pool-rotation-fix.md)：分池动态旋转的表达式约束。
- [箱子朝向偏转 180 度问题复盘](../sable/docs/sublevel-chest-rotation-fix.md)：箱子基准面和绝对朝向校准。

## 1. 不可违反的原则

1. **最终目标是世界中的可见结果。** 坐标值相同、两个渲染路径结果相同、离线测试通过，都不能单独证明朝向正确；必须证明模型的实际可见面指向正确的世界方向。
2. **状态语义优先于状态数字。** `direction: 1`、`cardinal_direction: west` 和 `pillar_axis: x` 不是同一种编码，不能套用同一条公式。先把状态解释成方向、轴或附着面，再使用该模型的映射表。
3. **模型基准面优先于 TreePhysics 角度。** 先确认 Sable 中未旋转模型的实际前面，再计算每个状态需要的局部旋转。TreePhysics 的公式只在坐标投影、模型基准面和骨骼组合完全相同的情况下可直接复用。
4. **三条渲染路径必须语义一致。** 独立密集模型、独立稀疏模型和共享池模型必须使用相同的方块几何、位置、方向映射和状态语义。池化只能改变数据打包和资源复用，不能改变方块结果。
5. **不要把数学等价当成 Bedrock 等价。** Bedrock 原生客户端对生成的 Molang/动画表达式才是实际执行者。已知正确的条件选择结构应原样保留；即使 JavaScript 或其他解释器算出的结果相同，也不能擅自改成另一种表达式结构。

## 2. 坐标空间

Sable 中必须区分以下空间，任何转换都要明确写出输入和输出空间。

### 2.1 世界方块空间

Minecraft 世界使用右手坐标约定：

- `+X`：东（east）
- `+Y`：上（up）
- `+Z`：南（south）
- `-X`：西（west）
- `-Y`：下（down）
- `-Z`：北（north）

方块位置是整数格坐标。方块的几何范围是该格的闭开区间 `[x, x+1) × [y, y+1) × [z, z+1)`；比较方块位置时比较格坐标，不比较模型实体的浮点位置。

### 2.2 Sable 投影空间

Sable 将世界坐标投影到模型实体空间时保留 `X/Y`，反转 `Z`：

```text
project(x, y, z) = ( x,  y, -z )
```

因此：

- 世界东仍是模型 `+X`；世界西是模型 `-X`。
- 世界上仍是模型 `+Y`；世界下是模型 `-Y`。
- 世界南 `+Z` 变成模型 `-Z`；世界北 `-Z` 变成模型 `+Z`。

一个方块等于 16 个模型单位。以结构原点 `O` 为基准时，方块相对位置 `(dx, dy, dz)` 的模型平移为：

```text
modelPosition = (16 * dx, 16 * dy, -16 * dz)
```

这条负号只属于位置投影；不能因为位置使用负 `Z`，就自动把所有局部旋转角度也按 TreePhysics 公式反转。

### 2.3 模型资源空间

模型骨骼、立方体、枢轴和贴图面使用资源包的局部坐标。资源空间中的 `north/south/east/west` 是模型几何的面名，不能直接当成世界方向。经过 Sable 的 `Z` 投影后，模型面名与世界面可能相反；每一种有方向的模型都必须先记录它的“零旋转基准面”。

### 2.4 实体和方块局部空间

渲染实体承载结构的全局姿态，方块 `slot` 承载方块在结构内的位置和自身状态旋转：

```text
世界方块位置
  -> Sable 投影平移
  -> 结构实体的全局姿态
  -> slot 的方块局部旋转
  -> 模型骨骼和枢轴变换
```

方块方向属于 `slot` 局部变换，不得通过修改 slot 的格子位置来“补偿”方向。实体全局姿态改变的是整个子世界，不能代替方块自身的朝向状态。

## 3. 旋转组合

Sable 的结构姿态按固定骨骼链组合：

```text
root -> pitch -> roll -> yaw -> model_offset -> slot -> 方块模型骨骼
```

- `root`：实体身体姿态的基础补偿。
- `pitch`、`roll`、`yaw`：结构实体的连续姿态。
- `model_offset`：结构原点在实体中的模型单位偏移。
- `slot`：方块的格子位置、可见性和方块状态旋转。
- 方块模型骨骼：模型自身的枢轴、盖子、果柄、附着面等局部细节。

全局姿态与方块局部姿态必须分开保存和计算。对结构做旋转时，所有 slot 一起旋转；对箱子、蜂巢、可可果等有方向方块做旋转时，只改变对应 slot 的局部方向。

### 3.1 角度的书写规则

- 所有旋转统一写成 `[pitch, yaw, roll]`，单位为度。
- 角度可用 `-90`、`90`、`180` 等等价值，但要保持该模型已经验证过的写法；不要为了“看起来更合理”自行换符号或归一化。
- 世界方向判断以模型最终可见面为准，不能只检查属性中的数值。
- 结构全局旋转和方块局部旋转不相加成一个新状态；它们在各自骨骼层级按固定顺序组合。

## 4. 方块状态到方向的通用规则

没有一条适用于所有方块的 `state -> yaw` 通用公式。新增有方向方块时，按以下顺序处理：

1. 确定状态的语义：水平四方向、六面方向、三轴方向、附着面集合，还是模型变体选择。
2. 找到模型的零旋转基准面，并在 Sable 投影后确认它实际指向的世界面。
3. 对每一个合法状态建立“状态值 -> Sable 局部旋转 -> 最终世界面”的表格。
4. 让独立密集、独立稀疏和池模型都使用这张表；池模型只把表中的结果按 family 条件选择出来。
5. 用四个水平面或全部合法面做绝对方向验证。只验证一个方向、只验证 Z 轴，或只验证两条路径相同，都不够。

### 4.1 状态类型的处理方式

| 状态类型 | 解释方法 | 约束 |
| --- | --- | --- |
| `cardinal_direction` | 直接解释为 `north/east/south/west` | 仍须校准模型零旋转基准面；不能套用 `direction` 数字表。 |
| `direction` | 先按该方块的原版语义解码为四个水平面 | 不同方块的数字含义可能不同；蜂巢的表不能用于箱子或其他方块。 |
| `facing_direction` | 先解码为六个世界面 | 水平面与上下方向分开验证；不要把六向数字当成四向数字。 |
| `pillar_axis` | 解码为 `x/y/z` 轴 | 这是轴向，不是水平朝向；模型需验证绕对应枢轴的整体旋转。 |
| 面位集合（如藤蔓） | 解码为附着面集合 | 通过选择/隐藏对应面骨骼表达，不使用一个统一 yaw。 |
| 自定义状态 | 由注册表的 `variants` 明确选择模型和旋转 | 所有被条件引用的状态必须注册；未知组合回退到 `default` 或 `vanilla`。 |

## 5. 已校准的方向映射

以下是目前已经通过游戏内复测的 Sable 映射。它们是模型专用规则，不是全局状态公式。

### 5.1 蜂巢：`minecraft:direction`

蜂巢的资源模型在 Sable 投影中的零旋转基准与 TreePhysics 不同，必须使用下表：

| 原版状态 | Sable 局部 Yaw | 最终世界朝向 |
| ---: | ---: | --- |
| `0` | `-180°` | 南（`+Z`） |
| `1` | `-90°` | 西（`-X`） |
| `2` | `0°` | 北（`-Z`） |
| `3` | `90°` | 东（`+X`） |

等价公式为：

```text
yaw = (direction - 2) * 90
```

状态 `0` 和 `2` 的 Z 轴结果保持不变，状态 `1` 和 `3` 的 X 轴结果必须按 Sable 的顺序表达。TreePhysics 的 `direction === 0 ? 0 : 4 - direction` 只适用于 TreePhysics 自身的投影和模型组合，不能直接搬到 Sable。

### 5.2 箱子：`minecraft:cardinal_direction`

箱子模型在 Sable 中的未旋转正面已经验证为世界南。箱子的方向编码表为：

| 原版方向 | Sable 局部 Yaw |
| --- | ---: |
| `south` | `0°` |
| `west` | `90°` |
| `north` | `180°` |
| `east` | `270°`（等价于 `-90°`） |

箱子曾出现“转换前朝北、转换后朝南”的固定 180° 偏转。根因是公共旋转公式额外加了 180°；不是方块状态丢失、格子位置错误、箱盖动画错误或分池本身错误。以后不得在箱子通用公式外再加固定 180° 偏移。

### 5.3 原木与柱状模型：`pillar_axis`

原木问题的根因不是坐标投影，也不是分池策略，而是池模型把多个条件旋转结果写成相加的三元表达式。Bedrock 客户端中，这种写法与 TreePhysics 的已验证条件选择写法不等价，导致水平原木被显示为竖直原木。

实现柱状模型时：

- `y` 表示默认竖直轴，保持模型的零旋转姿态。
- `x`、`z` 表示水平轴，按模型枢轴和已验证的整体旋转表达。
- 池模型必须使用互斥的条件选择链；相同角度的 family 条件可以用 `||` 合并，不得把多个“条件成立则角度，否则 0”的结果相加。

## 6. 分池、稀疏和密集模型

### 6.1 数据层

- dense 通过固定槽位和布局尺寸解码位置。
- sparse 通过每个槽位的编码字解码位置和占用状态。
- pool 通过槽位中的占用位、family 位和可选 state 位解码成员模型、交互状态和可见性。

三种格式的位布局可以不同，但解码后的语义必须相同：同一方块拥有同一格坐标、同一模型、同一方向、同一交互状态。

### 6.2 旋转层

池模型的 family 只决定“这个槽位使用哪个成员模型及其局部变换”。方向选择必须是条件分支：

```text
family 满足条件 A -> 角度 A
否则 family 满足条件 B -> 角度 B
否则 -> 0
```

不要将不同 family 的候选角度相加。即使 family 在数学上互斥，Bedrock 对表达式的解析和动画执行也可能不等价；TreePhysics 已验证的条件选择结构是兼容性标准。

### 6.3 一致性要求

同一个有方向方块必须在以下场景中保持逐项一致：

- 独立 dense 与独立 sparse；
- 独立模型与共享 pool；
- 单一 family 与混合 family；
- 结构静止与结构整体旋转；
- 箱子关闭与打开；
- 方块存在、被破坏、被放置和被交互时的模型状态。

## 7. 新方块的标准接入流程

### 7.1 建立方向表

在注册表中确定模型、状态和变体后，先写一张方向表，至少包含：

| 项目 | 必填内容 |
| --- | --- |
| 状态语义 | 原版状态名、合法值、对应世界面或轴 |
| 零旋转基准 | 未旋转模型的资源前面，以及它在 Sable 中的世界面 |
| 局部旋转 | 每个状态的 `[pitch, yaw, roll]` |
| 预期结果 | 每个状态最终可见面朝向的世界方向 |
| 模型路线 | dense、sparse、pool 是否都覆盖 |
| 特殊状态 | 盖子、附着面、阶段、开关等是否需要额外骨骼状态 |

没有方向表就不应直接复制 TreePhysics 的角度。

### 7.2 添加回归样本

测试结构至少包含：

- 方块的所有水平朝向；
- `pillar_axis` 的三个轴（如果支持）；
- 上下方向（如果支持）；
- 同一方块的独立模型与池模型一一对应样本；
- 至少一个有交互状态的开关前后样本（箱子要包含关闭和打开）。

每一排样本必须一一对应，不能只观察“看起来有四个方向”。记录方块格坐标、状态值、预期世界面和实际可见面。

### 7.3 游戏内验证

验证顺序固定为：

1. 先确认方块仍在原格子，排除位置编码错误。
2. 再确认模型基准面，验证南北两个方向。
3. 再验证东西两个方向，专门捕捉 X 轴互换或 180° 偏转。
4. 再比较 dense、sparse、pool 两条或三条路径。
5. 最后验证整体运动、交互动画、声音、粒子、破坏覆盖层和放置/破坏行为。

离线回归只能证明资源生成、状态捕获和表达式结构符合预期，不能替代 Bedrock 客户端的最终视觉验证。尤其是动态 Molang 的条件组合，必须在与 TreePhysics 相同的游戏版本中做一次对照。

## 8. 已知失败模式与排查顺序

### 8.1 “所有模型都变成默认方向”

按顺序检查：

1. 方块状态是否被捕获并持久化；
2. variant 是否按状态选择；
3. slot 是否承载对应局部旋转；
4. pool family/state 位是否解码；
5. 三条路径是否使用同一张方向表。

只有前四项都正确，才检查模型几何本身。

### 8.2 “Z 方向正确，X 方向相反”

优先怀疑 TreePhysics 的方向反转公式被直接复用。只测北/南时，X 轴的两项错误不会出现；必须同时测试东西两项，并检查最终世界面，而不是检查角度数字是否相同。

### 8.3 “两排模型互相一致，但全部偏转 180°”

这通常表示两条路径共享了同一个错误的基准面或固定偏移。两排一致只能证明路径一致，不能证明绝对方向正确。箱子固定 180° 偏转就是此类问题。

### 8.4 “只有池模型中的原木错”

优先检查池动画是否把条件旋转写成相加表达式。分池策略本身不是根因；应先恢复 TreePhysics 已验证的条件选择结构，再重新生成池资源。

### 8.5 “位置和动画正常但朝向错误”

位置正确只能证明 slot 编码正确，盖子抬起只能证明交互状态和局部动画正确。两者都不能证明模型前面朝向正确；必须做绝对世界面检查。

## 9. 完成标准

一个方块的坐标和方向迁移只有同时满足以下条件，才算完成：

- 所有合法状态在 Sable 中与 TreePhysics 的最终可见方向一致；
- 所有支持的方块格子位置逐一对应；
- dense、sparse、pool 三条路径结果一致；
- 结构整体运动不改变方块相对朝向；
- 交互状态（包括箱盖开合）不改变错误的基准面；
- 方块编辑、声音、粒子、轮廓、破坏覆盖层和容器交互沿用原版行为；
- 离线回归通过，并完成同版本游戏内四方向对照；
- 新的特殊方向规则已经补充到本文的“已校准映射”或对应注册文档。

如果只满足“数值和 TreePhysics 一样”或“两个 Sable 路径一样”，不得标记为完成。

## 10. 本规范的维护方式

每次发现新的坐标问题，都要在修复后补充三项内容：

1. 错误发生在哪个坐标空间或哪一层变换；
2. 为什么状态、位置或离线测试没有提前暴露它；
3. 新方块以后应遵守哪条可复用规则。

个案修复文档保留完整复盘，本规范只吸收已经确认、可以推广的规则。若新结论与本文冲突，必须先更新方向表和验证标准，再修改实现；不能仅凭 TreePhysics 的旧角度或一次离线结果覆盖本规范。
